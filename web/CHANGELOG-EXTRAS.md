## 2026-11-18

- ICS 204 assignment sheet (Task 4, P-10): `ics204Sheets` lays the plan onto the FEMA ICS 204 v3.1 blocks (titles copied from the form PDF, read 2026-11-18), ten resource rows per sheet with Leader, # of Persons and Contact left blank for a pen (the product stores no names or phone numbers), the drill line "Training drill. Nobody is missing. Do not dial 911.", the map match code with plan version and report count, and the approach notes only when "Include the approach notes" is ticked (off by default). `Ics204View` and `PrintRoot` render it for printing. Orchestrator fix before commit: approach notes on paper come from an allowlist of how-to-approach guidance only; a note about health, medication, mobility or risk to searchers never prints, even when ticked, because which notes appear reveals the person's conditions. `laneC.ts` also points MapLibre at its bundled worker (the same fix as lane-web 3cf7bd0), which the export check needs. Source: PLS-EXTRAS-PLAN Task 4; built in the Codex build lane, reviewed by the orchestrator. Verified: the tests failed first, then 13 pass, including the privacy grep and the new health-note test, which failed before the allowlist; `bash scripts/ci-local.sh` exit 0 on the series head.
- Print model (Task 3, P-09 and P-10): `buildPrintModel` builds the ICS 204 and radio card data from an allowlist only (incident name, mode, drill label; each team's id and name; the highest plan's assignments: segment ids, task text, reason), with the drill line "Training drill. Nobody is missing." when the stored label is missing; `isStale` raises the reprint line when a newer plan exists. Stored plans are approved by construction (`approvedByUid` and `approvedAt` are written with every plan), so the highest version is the highest approved one. Firestore timestamps become milliseconds through `toMillis()`, else `createdClientTimeMs`. Test fixtures in `testdata/fixtures.ts` (tests only). Source: PLS-EXTRAS-PLAN Task 3; built in the Codex build lane, reviewed by the orchestrator. Verified: the tests failed first, then pass, including the privacy test (the serialized model never matches uid, joinCode, approvedBy, profile or authorUid, even when those words are planted in text fields); web suite 228 passed; `bash scripts/ci-local.sh` exit 0.
- Radio match code functions (Task 2, P-09): `normalizeHeardCode` (trims, upper-cases, drops spaces and hyphens, reads I and L as 1 and O as 0, refuses U, symbols and any length but 4), `compareCodes` (same, different, or no code here yet), `PHONETIC` and `spellCode`. The words are the telephony words printed in the FAA Aeronautical Information Manual, paragraph 4-2-7 (read 2026-11-18): Alfa to Zulu, spelled Alfa, Juliett and Xray, and digits Zero to Nine; Crockford has no I, L, O or U. No new code scheme: the card reads the engine's existing 4-character match code. Source: PLS-EXTRAS-PLAN Task 2; built in the Codex build lane, reviewed by the orchestrator, who checked the word list at the FAA source. Verified: the tests failed first (module missing), then pass, including the engine alphabet test over 500 hashes with all 32 characters seen; `bash scripts/ci-local.sh` exit 0 on the series head.
