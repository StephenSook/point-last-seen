## 2026-11-18

- Replay data (Task 7, P-40 and P-38): `replay/replayData.ts` turns the live command post state (`fromLive`) or the published drill run (`fromPublishedRun`) into one ordered list of reports with the same sent and arrived times as the merge lanes (sent = phone clock plus the device's measured offset, arrived = server time), a clock-suspect flag for a negative or over-24-hour gap, pending writes last with no arrival time, and a person-in-view interval for a camera sighting only when its camera clock was confirmed. The prior is built exactly as the command post builds it (segment priors plus the outside-the-map mass), with the same fallback to the shared engine constants. A run file with a missing part, a report with no arrival time or a plan with no approval time is refused with a plain reason; nothing is guessed. `laneC.ts` now also re-exports `DEFAULT_PARAMS`. The published run's inner shapes are NOT VERIFIED until the export exists; the adapter reads the shape the export is asked to write (numeric `serverTimeMs` per report, `approvedAtMs` per plan, `clockOffsetMs` per device, segments as stored with the `ROW` mass). Test data in `testdata/replay.ts` (tests only). Source: PLS-EXTRAS-PLAN Task 7. Verified: the tests failed first (module missing), then 14 pass, including parity with `mergeModel` on the same docs and the same `viewState` match code as the command post's prior; web typecheck exit 0; `bash scripts/ci-local.sh` exit 0 (web suite 326).

It does not say where a person is." `ExportButton` downloads it as `pls-<incident>-plan-v<N>-<UTC>.geojson`. Source: PLS-EXTRAS-PLAN Task 6; built in the Codex build lane, reviewed by the orchestrator. Verified: the tests failed first, then 11 pass; the browser check loads the exported text into a MapLibre GeoJSON source and queries every segment; `bash scripts/ci-local.sh` exit 0 on the series head. Not run: an `ogrinfo` check (not installed here); whether CalTopo or SARTopo import it is NOT VERIFIED, so no surface names them.
