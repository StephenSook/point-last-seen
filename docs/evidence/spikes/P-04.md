# P-04: server prompt templates with media and audio

Run 2026-11-18 about 21:25 UTC against the live project, through `templateGenerateContent` on the Gemini
Developer API (`projects/buildhybridai-2026-yg3m/templates/{id}:templateGenerateContent`), the way a signed-in
browser calls it: the site's Referer, a limited-use App Check token from the web debug token, and a Firebase
ID token from a throwaway anonymous user (deleted afterwards). Three spike templates were created by the REST
API and deleted after the run. Results are in `P-04.json`.

| Question | Template | Input | Result |
|---|---|---|---|
| Inline image (web photo read) | `gemini-3.5-flash-lite`, `{{media type=mimeType data=imageData}}` | a 17,148-byte JPEG test card | WORKS: 200 in 1.6 s, a text answer naming the colours |
| 14 MB inline video (web and Android clip read) | `gemini-3.5-flash-lite`, `{{media type=mimeType data=videoData}}` | a 13,788,183-byte H.264 MP4 (under our 14,000,000-byte limit), sent inline as base64 | WORKS: 200 in 18.7 s, a text answer describing the clip |
| Text to speech (iOS cloud voice) | `gemini-3.8-flash-lite-tts`, config `responseModalities: ["AUDIO"]`, voice Kore | one assignment sentence | WORKS: 200 in 2.8 s, `audio/wav`, 318,750 bytes |

Notes:
- The media helper takes request variables for both the type and the data, so one template serves any clip or
  photo the client has already checked (size, type, consent).
- The test media were made with ffmpeg (`testsrc2`), not real footage.
- Not measured here: streaming (`templateStreamGenerateContent`), and the Kotlin and Swift template clients
  (only REST was called).
