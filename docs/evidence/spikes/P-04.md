browser calls it: the site's Referer, a limited-use App Check token from the web debug token, and a Firebase

Notes:
- The media helper takes request variables for both the type and the data, so one template serves any clip or

- Not measured here: streaming (`templateStreamGenerateContent`), and the Kotlin and Swift template clients
  (only REST was called).

## The clip window (videoMetadata) cannot pass through a template

Run 2026-11-18 about 21:40 UTC, same path. The test clip is 12 seconds: 4 s red, 4 s blue, 4 s green (ffmpeg
`color` sources), with the question "List every background colour shown in this clip".

| Call | Window asked for | Answer | Prompt tokens |
|---|---|---|---|
| Template, `{{media type=mimeType data=videoData}}` | none | red, blue, green | 808 |
| Template, `{{media type=mimeType data=videoData startOffset=startOffset endOffset=endOffset}}` | 4 s to 8 s as variables | red, blue, green | 808 |
| Direct `generateContent`, part `videoMetadata: {startOffset: "4s", endOffset: "8s"}` | 4 s to 8 s | blue | 281 |

The template accepts the extra arguments and ignores them: the whole clip reaches the model. So a clip read
that must send only a flagged span (the web's triage window) stays a direct call with `videoMetadata`; a read
of the whole clip can use a template.
