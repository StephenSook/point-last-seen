## Step 4: `LanguageModel` deleted, the gate, and two positive controls

A local page with firebase 13.4.0 (`@firebase/ai` 3.1.0) from npm, App Check in debug mode (a registered debug token, kept outside the repo), the Gemini Developer API backend, and `gemini-3.5-flash-lite`. An inline classic script deletes `self.LanguageModel` before any module runs; the page confirmed `typeof LanguageModel === "undefined"`. Requests were recorded with the Chrome DevTools Protocol `Network` domain during each call. The prompt was a fixed non-private sentence.

| Arm | Code path | Result | Requests to `firebasevertexai.googleapis.com` |
|---|---|---|---|
| Gate on, `LanguageModel` deleted | `runOnDeviceOnly(onDeviceCreateOptions("text"), () => model.generateContent(text))`, model in `InferenceMode.ONLY_ON_DEVICE` | `ran: false`; the SDK call was never made | 0 (no request of any kind) |
| Gate off, `LanguageModel` deleted (control 1) | the same `ONLY_ON_DEVICE` model, `generateContent` called directly | answered, `inferenceSource` "in_cloud" | 1 POST, HTTP 200 (plus its CORS preflight and one App Check debug exchange) |
| Explicit cloud call (control 2) | `InferenceMode.ONLY_IN_CLOUD` | answered, `inferenceSource` "in_cloud" | exactly 1 POST, HTTP 200 |
| Gate on, model present | the gated `ONLY_ON_DEVICE` call on a normal page | `ran: true`, `inferenceSource` "on_device", 11,746 ms (first session in a new tab) | 0 |

What this shows:
- Control 1 reproduces firebase-js-sdk issue #10635 on our pinned release: with no `LanguageModel`, `ONLY_ON_DEVICE` sends the prompt to the cloud. Checking `inferenceSource` afterwards would be too late, because the prompt has already left.
- The gate stops that call before it reaches the SDK, so nothing is sent.
- Controls 1 and 2 prove the recorder sees AI Logic requests, so the 0 in the gated arm is a real 0.
- Deployed tests count POST requests only, because each cross-origin call also sends an OPTIONS preflight.

## SDK defaults found while building the gate

`@firebase/ai` 3.1.0 sets default on-device `expectedInputs` to English text AND image (`dist/esm/index.esm.js`, the constant `defaultExpectedInputs`, lines 912 to 915 in the installed package), and asks Chrome's availability check with `this.onDeviceParams.createOptions` (line 980). So an on-device text read that does not set its own `expectedInputs` is checked for image support too, and on a browser with a text-only model it would report unavailable. `web/src/ai/gate.ts` builds every on-device create option in one place (`onDeviceCreateOptions`): `expectedInputs` English text, plus image only for photo reads, and `expectedOutputs` English text. The same object goes to the gate and to `onDeviceParams.createOptions`, so the gate asks Chrome the same question the SDK asks.

What the misses say for Task 20:
- On the stock profile, two replies failed with "The response exceeded output limits and was truncated". Task 20 caps `visibleText` and keeps the schema short.

- With n = 20 these counts are a go or no-go gate, not an accuracy claim.
