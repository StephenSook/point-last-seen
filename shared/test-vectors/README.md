# Shared test vectors

`search.json` is generated by `tools/vectors/make_vectors.py`, a standard-library
Python reference of the engine. The TypeScript engine (`shared/engine-ts`) and the
Swift twin (`ios/PLSCore`) must reproduce every `expected` value. Never edit
`search.json` by hand: change the generator and run

```
python3 -I tools/vectors/make_vectors.py
```

CI regenerates the file and fails on any difference.

## Comparer

Number leaves match within 1e-12 relative (absolute 1e-12 when the expected value
is 0). Strings, booleans, null, array order and object key sets match exactly.
A key whose value is null is present, never omitted.

## File shape

```
{ "sections": ["pod", "trackLength", "ioc", "posterior", "orderIndependence", "deriveEffect",
               "docToEngine", "rank", "ids", "router", "evidence"],
  "<section>": [ { "name": string, "input": object, "expected": any } ] }
```

`router` is Swift only. Every other section runs in both engines.

## Inputs and expected values per section

`params` below is always the full `params` object of
`shared/constants/engine-params.json` (sometimes with `detectionProfile` changed).

| Section | input | expected |
|---|---|---|
| pod | `{ coverage }` | number, `1 - exp(-coverage)` |
| trackLength | `{ minutes, searchers, searchType, params }` | number, `speed x (minutes x 60) x searchers`; `hasty` uses `hastySpeedMps`, `sweep` and `unknown` use `sweepSpeedMps` |
| ioc | `{ influence, authenticity, params }` | number, `1 - authenticityWeight[a] x (1 - iocBase[i])` |
| posterior | `{ prior: SegmentPrior[], events: EngineEvent[], params }` | `PosteriorResult` |
| orderIndependence | same as posterior, events shuffled or repeated | `PosteriorResult` of the sorted, deduplicated events |
| deriveEffect | `{ fn: "cleared", reading, ctx, params }` or `{ fn: "clue", reading, ctx }` | `Effect` |
| docToEngine | `{ docs: EventDoc[], priorInputEventIds: string[] }` | `EngineEvent[]` |
| rank | `{ result: PosteriorResult, prior: SegmentPrior[] }` | `RankedSegment[]` |
| ids | `{ fn: "eventId", incidentId, deviceId, seq }` | `{ eventId }` |
| ids | `{ fn: "eventSet", priorVersion, eventIds }` | `{ eventSetHash, convergenceCode }` |
| ids | `{ fn: "convergenceCode", hash }` | `{ convergenceCode }` |
| router | `{ fn: "decide", input: RouterInput }` | `{ path, reason }` |
| router | `{ fn: "afterFailure", failure, path, stage }` | `{ next: "stage", stage }`, `{ next: "pick_list" }` or `{ next: "reroute_without_on_device" }` |
| evidence | `{ text }` | boolean |

## Types used above

```
SegmentPrior   = { segmentId, priorPoa }                       // "ROW" is the reserved outside-the-grid entry
EngineEvent    = { eventId, effect: Effect }                   // vectors may add iocOverride: { [segmentId]: number }
PosteriorResult = { poa: { [segmentId]: number },
                    remainingMass: { [segmentId]: number },    // priorPoa x product over clears of (1 - pod)
                    cumulativePod: { [segmentId]: number },    // 1 - product over clears of (1 - pod)
                    appliedEventIds: string[], ignoredEventIds: string[] }
RankedSegment  = { segmentId, rank, poa, priorPoa, deltaPoa }  // ROW left out; poa descending, then segmentId; rank from 1
Ctx = { segments: { [segmentId]: { areaM2, neighbors: [{ segmentId, bearingDeg }], upstream: string[], downstream: string[] } },
        assignedSegmentIds: string[], visualDetectionRangeM: number | null,
        rdBasis: "hidden_target" | "open_target" | "default",
        position: { lat, lon, accuracyM } | null, positionSegmentId: string | null }
RouterInput = { taskClass, networkOnline, onDeviceAvailable, localeSupported, estimatedTokens,
                contextSize, tokenBudgetFraction, cloudConsent, killCloud }
```

`reading` is a full `ReportReading` and `docs` are full `EventDoc` objects (spec
section 8); `serverTime` is null in vectors.

## Rules the vectors pin

Posterior
- Apply events in ascending `eventId` order and skip a repeated `eventId`.
- A clear multiplies its segment by `1 - pod`. A clear whose segment is not in the prior is ignored.
- A clue multiplies every prior entry, ROW included, by its IOC. Entries the effect does not list are "neutral". A clue that lists no prior entry is ignored. With `iocOverride`, listed entries take the given factor and unlisted entries are unchanged.
- An effect of kind "none" is ignored. Ignored ids go to `ignoredEventIds` in event order.
- Sum the weights in prior order. `poa = w / sum`; a zero sum gives 0.

Effect derivation (`fn: "cleared"`), checks in this order
1. `reading.kind` is not "cleared": none / invalid.
2. `method` is "sound" and `detectionProfile.soundCounts` is false: none / sound_only.
3. Segment: first `segmentIds` entry present in `ctx.segments`, else the first assigned one; none found: none / needs_command.
4. Coverage normalization: 0 to 3 kept; above 3 and up to 300 divided by 100; else (or not finite) none / invalid.
5. Stated coverage: `C` is that value; `sweepWidthM` and `trackLengthM` are null; `rdBasis` is `ctx.rdBasis`.
6. Otherwise `Rd` is the team's measured `ctx.visualDetectionRangeM` (then `ctx.rdBasis`), else `reading.detectionRangeM` (then `rdBasis` "stated"). A model-read range never overrides a measurement (spec 10.4). Missing minutes, searchers or `Rd`: none / needs_command. `W = 1.645 x Rd`, `C = (W x L) / A`.
7. Result `{ kind: "cleared", segmentId, pod, inputs: { coverage, sweepWidthM, trackLengthM, areaM2, rdBasis } }`.

Effect derivation (`fn: "clue"`), for kinds "clue" and "sighting"
- Other kinds: none / invalid.
- With a position, the segment is `ctx.positionSegmentId`; null or unknown: none / outside_area.
- Without a position, the first known `segmentIds` entry, else the first assigned one; none: none / needs_command.
- That segment is "strong_for". For a compass direction, each neighbor whose `bearingDeg` is within 45 degrees (inclusive) is "for". "upstream" and "downstream" mark that list. Neutral entries are not listed.
- Authenticity: consistent gives high, unknown medium, inconsistent low.

Events to the engine (`docToEngine`)
- Deduplicate by `eventId` (first copy wins); output sorted by `eventId`.
- Skip any doc whose stored effect is malformed (same shape the security rules enforce: exact keys per variant,
  known enums, finite numbers in bounds, at least one clue influence). Never throw on one; command can list
  them with `malformedEventIds`.
- Skip ids in `priorInputEventIds`, and retracted ids. A retraction counts from role command or from the target's own `authorUid`.
- `cleared` counts when its effect is a clear whose `inputs.coverage` is finite and at least 0 and whose `pod` is within 1e-9 of `1 - exp(-coverage)`. Computed coverage may exceed 3.
- `clue` counts when its effect is a clue with authenticity high or medium.
- `sighting` counts like a clue only when the deciding confirmation targeting it says "confirmed". Confirmations count from role command or family. A command confirmation outranks any family one (the writer sets `clientTimeMs`, so a skewed family clock must not override command); within one role the latest by (`clientTimeMs`, `eventId`) decides. A retracted confirmation does not count.
- `camera_sighting`, `destination`, `confirmation`, `retraction`, `found` and `plan_ack` never count.

Ids
- `eventId`: SHA-256 over the UTF-8 string made of, per field (incidentId, deviceId, decimal seq), the
  decimal UTF-8 byte length, a colon and the value; the first 16 bytes as 32 lowercase hex characters.
  Worked example: ("ab", "c", 1) hashes the string `2:ab1:c1:1`; ("a", "bc", 1) hashes `1:a2:bc1:1`.
  The security rules rebuild this string, so an event can only be created at its own id.
- `eventSetHash` framing: each field is a 4-byte big-endian byte length, then its UTF-8 bytes.
- `eventSetHash`: deduplicate the ids, sort by code point, SHA-256 over [decimal priorVersion] + sorted ids; 64 lowercase hex characters. An empty set hashes the priorVersion field alone.
- `convergenceCode`: the first 20 bits of the hash, 4 groups of 5 bits, most significant first, through `0123456789ABCDEFGHJKMNPQRSTVWXYZ`.

Router (Swift only)
- `decide`: step 1 fails, in order, on `onDeviceAvailable` (on_device_unavailable), `localeSupported` (locale_unsupported), `contextSize <= 0` or `estimatedTokens > contextSize x tokenBudgetFraction` (over_token_budget). Step 1 passes: on_device with on_device_default online, no_network offline. Else cloud when online, consented and not killed, with the step 1 reason. Else rules with the step 1 reason.
- `afterFailure`: at `deterministic_parser` or `evidence_protocol`: `{ next: "pick_list" }`. A `guardrail_block` or `refusal` on path on_device at stage guided: permissive_text; elsewhere deterministic_parser. A block or refusal never leads to the cloud. `unavailable` or `context_exceeded` on path on_device at stage guided: `{ next: "reroute_without_on_device" }` (decide again with on-device marked unavailable); elsewhere deterministic_parser. Every other failure (`parse_failed`, `network`, `app_check_refused`, `cancelled`, `other`): deterministic_parser.

Evidence pre-screen
- See `matching` in `shared/constants/evidence-terms.json`.

## phone-numbers.json (hand-written)

The phone-number cases every platform that removes phone numbers from a note must pass. There is no generator: edit
the file by hand, and `scripts/test_phone_vectors.py` checks that the required cases are present and well formed.

- `mustRemove[]`: `{ name, input, number, forbidden, keep }`. Run the platform's scrubber on `input`. The output must
  not contain `number`, must contain no digit 0-9 (the number is the only digit run in `input`), must contain none of
  `forbidden` (parts of a number written in words), and must still contain every string in `keep` (the text around
  the number).
- `mustKeep[]`: `{ name, input }`. The output must equal `input` exactly: times, segment numbers, counts, percents
  and dates (11/19/2026, 2026-11-19, 11/19, Nov 19) are not phone numbers; a date in a note is search information.
  So are coordinates (`GPS 33.7490, -84.3880`), a ZIP+4 code, a grouped count (`1,234,567`), a street number and a
  number glued to a unit (`5km`).
- `exact[]`: `{ name, input, output }`. The output must equal `output` byte for byte, with the shared `replacement`
  (`[number removed]`, the token every platform writes) where the number was.
- `pendingOn` (optional, on any case): the platforms (`ios`, `web`, `android`) whose rule does not pass that case
  yet. A platform's runner skips a case that names it and runs every other case; when its rule passes, the platform
  is removed from the list. Every runner checks all three case types.

The reference rule is the Android family app's, `android/app/src/main/java/app/pointlastseen/family/core/PhoneNumbers.kt`
(the iPhone's matches it). Seven or more digits in a row are a number: written digits in any script (full-width and
Chinese numerals too) and spoken English digit words count alike, joined only by short separators (at most three
spaces, or `- . , ( ) /` or a dash such as U+2010 to U+2014 and U+2212; a CRLF counts as one). Search information made
of digits can sit inside such a run (a written date, a time, a coordinate pair, a grouped count, a ZIP+4 code after a
state, a month-name date, a number with a unit); it stays only when the rest of the run is nothing or whole numbers
of seven or more digits, and when any other piece of 1 to 6 digits is left beside it the whole run is removed. A number
with an ordinal ending (`67th`) never joins others.

## language.json (hand-written)

The language screen every platform runs before a note may go to the cloud read. The rule and its two word lists are
in `shared/constants/language-words.json` (`matching`); the web runs `looksEnglish` from `shared/engine-ts`. Run it on
the note as the person wrote it, before phone numbers are removed: the replacement token adds English-looking words,
and a short Russian or Chinese note with a number would then pass (both are pinned in `mustRefuse`).

- `mustAllow[]`: `{ name, input }`. The note looks English and may go to the cloud read: plain field notes, and
  English notes that quote Spanish names, places or phrases (the families this serves often do).
- `mustRefuse[]`: `{ name, language, input }`. The note does not look English: whole notes in Spanish, Portuguese,
  Vietnamese or Korean. The cloud read is refused; the on-device read and hand entry still work.
- `knownMiss[]`: `{ name, input, why }`. Cases the rule gets wrong on purpose, kept so every platform gets them
  wrong the same way; each currently passes as English.

Tuning, 2026-11-20: a one-sided rule (share of common English words) refused 22% of 325 English sentences from this
repository's docs at its working threshold, so the screen counts foreign function words against English ones instead;
with `minForeign` 3 and `foreignOverEnglish` 2 it refuses none of those 325 sentences and passes every case here.
